# 产品需求文档 (PRD)：Gesturing 轻量级鼠标手势软件

**文档版本：** V2.0

**产品代号：** Gesturing

**目标平台：** Windows 10/11

**技术栈：** C# / .NET 8 (AOT 发布)

------

## 1. 产品概述

### 1.1 产品背景与目标

针对 PC 浏览器重度用户在网页浏览过程中的高频操作（如前进、后退、关闭标签、恢复标签），市场现有手势软件普遍存在功能冗余、内存占用高、运行依赖复杂等问题。

Gesturing 旨在打造一款**开箱即用、极低系统资源占用**的 Windows 全局鼠标手势增强工具。本产品摒弃复杂的视觉反馈与轨迹绘制，专注于核心手势识别与快捷键映射，实现最高效的单手浏览体验。

### 1.2 核心价值主张 (Value Proposition)

- **轻量高效：** 基于 .NET 8 AOT 原生编译，单执行文件无运行时依赖，后台常驻内存 < 30MB。
- **专注高效：** 剔除冗余动画与屏幕绘图，采用纯后台逻辑判定，响应速度达毫秒级。
- **无感运行：** 静默常驻系统托盘，不干扰用户的日常桌面操作流。

------

## 2. 软件生命周期与基础架构

### 2.1 启动与路由逻辑

程序启动时需执行环境与配置检查，根据结果执行不同路由：

1. **单实例保护：** 通过命名 `Mutex`（如 `Global\Gesturing_SingleInstance`）检查是否已有实例运行。若已有实例，则通过进程间通信激活已有实例的设置窗口，随后自身退出。
2. **配置读取：** 尝试读取配置文件（路径策略见 2.3）。
3. **路由判定：**
   - **情景 A（初始化/配置为空）：** 若配置文件不存在，或解析后手势规则（`rules`）为空，程序禁止静默运行，直接唤起并前置【自定义配置界面】。
   - **情景 B（正常启动）：** 若配置有效且非空，程序完全静默启动，直接最小化驻留至系统托盘，并同时初始化全局鼠标钩子（Mouse Hook）。

### 2.2 系统托盘 (System Tray) 管理

程序运行期间无常驻主窗口，依赖 `NotifyIcon` 组件管理系统托盘。托盘右键菜单包含以下交互项：

- **设置 (Settings)：** 唤出【自定义配置界面】。若窗口已存在，则将其置顶获取焦点。
- **启用/禁用 (Enable/Disable)：** 状态拨动开关（Toggle）。禁用状态下，注销全局鼠标钩子，暂停一切手势识别及拦截。
- **开机自启 (Run on Startup)：** 状态拨动开关。通过 `Microsoft.Win32.Registry` 操作注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 写入或移除启动项。
- **退出 (Exit)：** 安全释放所有系统钩子，终结进程。

### 2.3 配置文件存储路径策略

采用便携模式与应用数据目录双策略：

- **便携模式：** 若程序同目录下存在 `portable.marker` 文件，配置文件 `config.json` 读写于程序所在目录。
- **标准模式（默认）：** 配置文件位于 `%APPDATA%\Gesturing\config.json`。若目录不存在，启动时自动创建。

### 2.4 手势作用域机制

手势仅在目标进程为浏览器类应用时激活，其他应用下右键完全透传，不进入采集态。

- **进程白名单：** 配置文件中维护 `target_processes` 列表，存储浏览器进程名（如 `chrome.exe`、`msedge.exe`、`firefox.exe`）。
- **判定逻辑：** 右键按下时，通过 `GetForegroundWindow` → `GetWindowThreadProcessId` 获取进程 ID，再通过纯 P/Invoke 调用 `OpenProcess` + `QueryFullProcessImageNameW` 获取进程名（避免 `Process.GetProcessById` 的托管对象分配与 GC 开销）。同时维护"窗口句柄 → 进程名"缓存，同一窗口仅查询一次。匹配成功则进入手势采集态；匹配失败则完全透传，不拦截任何事件。
- **默认白名单：** 首次启动时预置主流浏览器进程名。

## 3. 功能需求说明

### 3.1 手势识别引擎 (后台核心机制)

通过 P/Invoke 调用 `SetWindowsHookExW` 安装 `WH_MOUSE_LL` 全局低级鼠标钩子，构建手势状态机。

#### 3.1.1 钩子线程架构

全局低级鼠标钩子必须在独立线程中运行，该线程需维护消息泵：

- **钩子线程：** 独立线程，通过 `SetWindowsHookExW` 安装钩子，随后进入 `GetMessage` 消息循环。线程仅负责钩子回调分发，不做耗时操作。
- **钩子回调职责边界：** 回调内仅执行两项工作：① 对 `WM_RBUTTONDOWN` 做进程白名单判定（使用纯 P/Invoke + 缓存，详见 2.4），决定吞掉或透传；② 将坐标数据通过 `Channel<T>` 发送至主线程。手势方向计算、去重、匹配及 `SendInput` 调用均由主线程完成。
- **超时保护：** Windows 规定低级钩子回调若超过约 300ms 未返回，系统将跳过该钩子。因此回调内只做坐标读取与通道写入，确保微秒级返回。

#### 3.1.2 执行流程定义

1. **触发监听：** 拦截到鼠标右键按下 (`WM_RBUTTONDOWN`)，记录屏幕绝对坐标 $(x_0, y_0)$，记录当前前台窗口句柄 $h_w$，状态机进入"采集态"。
2. **轨迹采集与降噪：** 拦截鼠标移动 (`WM_MOUSEMOVE`)。
   - **防抖动处理：** 设置像素阈值（如 10px）。仅当当前坐标与上一次记录点直线距离超出阈值时，才记录新的有效位移点，并根据向量方向转化为基础方向因子：`U` (上), `D` (下), `L` (左), `R` (右)。
   - **去重处理：** 过滤连续相同的方向因子（例如将序列 `U-U-U-R-R` 压缩为有效动作 `U,R`）。
3. **结算与执行：** 拦截到鼠标右键抬起 (`WM_RBUTTONUP`)，结束采集。
   - **超时取消：** 若右键按下后超过 3 秒未抬起，自动取消采集态，补发标准右键单击事件透传，并重置状态机。
   - **短距判定 (右键透传)：** 若首尾坐标绝对直线距离 $< 15\text{px}$，判定为常规右键呼出操作。程序不执行任何映射，并利用 API 补发一个标准的右键单击事件，以正常触发系统或浏览器的右键菜单。**注意：** 由于白名单进程上的所有右键点击都会被钩子先吞掉、等抬起后再判定，右键菜单会产生轻微的体感延迟（通常 < 100ms），这是手势拦截机制的固有 trade-off。
   - **前台窗口校验：** 结算执行前，检查当前前台窗口句柄是否仍为 $h_w$。若前台窗口已变化（如手势过程中 Alt+Tab），放弃本次快捷键发送，静默丢弃。
   - **手势匹配：** 若位移有效，将压缩后的手势序列（如 `D,R`）与内存中的用户规则表进行精确匹配。
   - **指令发送：** 若匹配成功，通过 P/Invoke 调用 `SendInput` 模拟对应的键盘快捷键（如 `Ctrl + W`）；若匹配失败，静默抛弃该次操作。

### 3.2 自定义配置界面 (GUI)

采用 WinForms 构建极简配置界面。WinForms 对系统托盘、热键捕获、窗口置顶等需求天然支持。

> **AOT 兼容性注意：** .NET 8 WinForms 的 AOT 支持不完整，`DataGridView` 等复杂控件在 trimming 下有已知问题。开发阶段应尽早执行 AOT 编译验证；若遇到不兼容控件，优先用 `ListView` 等简单控件替代，或降级为 self-contained 单文件发布。

#### 3.2.1 规则录入区

- **手势动作录入：**
  - 提供四个方向按钮：`[↑ 上]`、`[↓ 下]`、`[← 左]`、`[→ 右]` 及一个 `[清除]` 按钮。
  - 用户依次点击方向按钮，只读文本框内实时追加显示方向序列（例如 `↓ →`）。
  - **长度限制：** 手势序列最大长度为 4 步。超出时忽略后续输入并在界面提示。
- **快捷键录入 (热键捕获)：**
  - 提供自定义 `TextBox` 控件，重写 `WndProc` 捕获 `WM_KEYDOWN` / `WM_SYSKEYDOWN` 原始键盘消息。
  - 当输入框处于激活（Focus）状态时，接管用户的物理键盘输入。
  - 直接显示用户的组合键键值（例如同时按下 Ctrl 和 W，显示为 `Ctrl + W`）。支持反复覆写，直至用户满意。
  - **合法性校验：** 拦截系统保留组合键（如 `Ctrl + Alt + Del`），在界面上提示"该快捷键被系统保留，无法使用"。
- **操作下发：** 提供 `[保存并添加]` 按钮，点击后将当前设定的手势序列与快捷键组合编入下方规则列表，并清空录入区。保存时校验手势序列唯一性，若与已有规则重复则提示并拒绝。
- **配置即时生效：** GUI 保存规则后，直接以引用替换方式更新内存中的规则表，手势引擎立即使用新规则，无需重启或文件 watch。

#### 3.2.2 规则管理区

- **数据展示：** 以 `DataGridView` 呈现已保存的规则集，列包含：手势序列、快捷键、删除操作。
- **编辑功能：** 每行提供 `[删除]` 按钮，允许用户移除不需要的规则。

#### 3.2.3 作用域配置区

- 提供可编辑的进程名列表（如 `chrome.exe`、`msedge.exe`、`firefox.exe`），用户可添加或移除目标进程。
- 列表下方说明文字："手势仅在这些进程为前台窗口时生效，其他应用下右键正常使用。"

## 4. 数据结构规范

程序的持久化配置存储格式为标准的 JSON 文本，约定文件名为 `config.json`，结构规范如下：

```json
{
  "auto_start": true,
  "is_enabled": true,
  "target_processes": [
    "chrome.exe",
    "msedge.exe",
    "firefox.exe"
  ],
  "rules": [
    {
      "gesture_sequence": ["L"],
      "hotkey": {
        "modifiers": [],
        "key": "BrowserBack"
      }
    },
    {
      "gesture_sequence": ["R"],
      "hotkey": {
        "modifiers": [],
        "key": "BrowserForward"
      }
    },
    {
      "gesture_sequence": ["D", "R"],
      "hotkey": {
        "modifiers": ["Ctrl"],
        "key": "W"
      }
    },
    {
      "gesture_sequence": ["U", "L"],
      "hotkey": {
        "modifiers": ["Ctrl", "Shift"],
        "key": "T"
      }
    }
  ]
}
```

**字段说明：**

- `target_processes`：手势作用域的进程名白名单，右键按下时仅当前台窗口属于列表中的进程时才激活手势采集。
- `gesture_sequence`：手势方向序列，元素取值为 `"U"` / `"D"` / `"L"` / `"R"`。规则列表中该字段必须唯一。
- `hotkey.modifiers`：修饰键列表，元素取值为 `"Ctrl"` / `"Alt"` / `"Shift"` / `"Win"`，不区分左右。
- `hotkey.key`：主键，使用 Windows 虚拟键码对应的友好名称（如 `"W"`、`"BrowserBack"`、`"F5"`）。

## 5. 非功能需求 (Non-Functional Requirements)

1. **性能标准：**
   - 系统资源闲置状态下，CPU 占用率须接近 0%。
   - 内存占用阈值：托盘常驻期间 < 30MB（GUI 关闭后应主动回收）。
2. **兼容性与稳定性：**
   - 支持多显示器环境下的坐标系计算，避免跨屏鼠标移动导致坐标突变引发的计算错误。
   - 长时间运行（> 7天）不出现句柄泄漏或内存泄漏。
3. **发布形态：**
   - .NET 8 AOT 编译为单执行文件，无需用户安装 .NET 运行时。
   - 预期文件体积 10-15MB。

## 6. 异常与边界情况处理 (Edge Cases)

| **场景描述**          | **预期处理逻辑**                                             |
| --------------------- | ------------------------------------------------------------ |
| **右键双击/快速连击** | 时间间隔过短的右键按下抬起操作，不触发手势采集，直接透传。   |
| **手势超时**          | 右键按下后超过 3 秒未抬起，自动取消采集态，补发右键单击事件透传，重置状态机。 |
| **系统权限冲突**      | 若在具有"管理员权限"运行的软件（如任务管理器）上方绘制手势失效，此为 Windows 权限隔离机制 (UIPI)。向用户说明本程序需同等或更高权限（以管理员身份运行）方可全局生效。 |
| **配置文件损坏**      | 程序启动解析 `config.json` 发生格式错误或 IO 异常时，做备份处理（重命名为 `.bak`），并按"情景 A"直接弹出设置界面重新初始化。 |
| **快捷键冲突**        | 若用户绑定的快捷键被系统强行霸占（如 `Ctrl + Alt + Del`），程序应在 GUI 界面捕获阶段即进行合法性校验并予以提示拦截。 |
| **手势规则重复**      | 保存规则时校验 `gesture_sequence` 唯一性，若与已有规则重复则提示并拒绝保存。 |
| **前台窗口切换**      | 手势结算执行前检查前台窗口是否仍为触发时的窗口，若已变化则放弃快捷键发送。 |
| **非作用域进程**      | 前台窗口进程不在 `target_processes` 白名单中时，右键事件完全透传，不进入采集态。 |
| **重复启动**          | 通过命名 Mutex 检测已有实例运行时，激活已有实例的设置窗口并退出自身，防止重复注册全局钩子。 |
| **手势序列过长**      | GUI 录入区限制手势序列最大 4 步，引擎匹配时若采集到超过 4 步的序列则静默丢弃。 |
