# Gesturing 开发计划

基于 PRD V2.0，按依赖关系拆分为 8 个阶段，每步可独立实现与验证。

---

## Phase 1：项目脚手架

| # | 任务 | 产出 | 验证标准 |
|---|------|------|----------|
| 1.1 | 创建 .NET 8 WinForms 项目 `Gesturing.csproj` | 可编译的空 WinForms 项目 | `dotnet build` 通过 |
| 1.2 | 配置 AOT 发布参数（`PublishAot`、`InvariantGlobalization` 等） | `.csproj` 中包含 AOT 相关属性 | `dotnet publish -c Release` 生成单文件 |
| 1.3 | 建立项目目录结构 | `Models/`、`Services/`、`Native/`、`UI/` 目录 | 目录存在，项目仍可编译 |

| # | 任务 | 产出 | 验证标准 |

## Phase 6：手势识别引擎（核心）

分为 3 个子阶段，逐步构建完整引擎。

### 6A：钩子基础设施

| # | 任务 | 产出 | 验证标准 |
|---|------|------|----------|
| 6.1 | 实现钩子线程（独立线程 + 消息泵 + 钩子安装/卸载） | `Services/MouseHookService.cs` | 钩子安装后能收到全局鼠标事件；卸载后停止 |
| 6.2 | 实现 `Channel<T>` 跨线程通信管道 | 同上 | 钩子回调写入坐标数据，主线程侧能读出 |
| 6.3 | 实现钩子回调中的进程白名单判定（调用 ProcessHelper） | 同上 | 白名单进程上右键被吞掉；非白名单进程右键透传 |

### 6B：手势状态机

| # | 任务 | 产出 | 验证标准 |
|---|------|------|----------|
| 6.4 | 实现状态机骨架（空闲态 → 采集态 → 结算态） | `Services/GestureStateMachine.cs` | 右键按下进入采集态，抬起进入结算态，结算后回到空闲态 |
| 6.5 | 实现方向计算（坐标差 → U/D/L/R，10px 防抖阈值） | 同上 | 给定坐标序列，输出正确的方向因子 |
| 6.6 | 实现方向去重（连续相同方向压缩） | 同上 | `U-U-U-R-R` → `U,R` |
| 6.7 | 实现手势序列长度上限（> 4 步静默丢弃） | 同上 | 采集超过 4 步方向后标记为无效 |
| 6.8 | 实现短距判定（< 15px 补发右键单击） | 同上 | 原地右键点击触发正常右键菜单 |
| 6.9 | 实现超时取消（3 秒计时器，超时补发右键 + 重置） | 同上 | 按住右键 3 秒后弹出右键菜单，状态机重置 |
| 6.10 | 实现前台窗口校验（结算时比对句柄） | 同上 | 手势过程中切换窗口，结算时放弃执行 |

### 6C：指令执行

| # | 任务 | 产出 | 验证标准 |
|---|------|------|----------|
| 6.11 | 实现手势序列匹配（压缩序列 vs 规则表精确匹配） | `Services/GestureMatcher.cs` | 序列 `D,R` 匹配到 `Ctrl+W` 规则 |
| 6.12 | 实现 SendInput 快捷键模拟（修饰键按下→主键按下→主键抬起→修饰键抬起） | `Services/InputSender.cs` | 在记事本中模拟 `Ctrl+A` 能全选文本 |
| 6.13 | 实现虚拟键码映射（友好名称 ↔ VK 码双向转换） | `Services/VirtualKeyMapper.cs` | `"W"` → `0x57`，`"BrowserBack"` → `0xA6` 等 |

## 依赖关系总览

```
Phase 1 ─→ Phase 2 ─→ Phase 4
               │
Phase 1 ─→ Phase 3 ─→ Phase 6A ─→ Phase 6B ─→ Phase 6C
               │                                    │
Phase 1 ─→ Phase 5 ◄────────────────────────────────┘
               │
               └──→ Phase 7 ─→ Phase 8
```

- Phase 2（配置）和 Phase 3（P/Invoke）可并行开发
- Phase 5（托盘）依赖 Phase 2（读取 `is_enabled` / `auto_start`）
- Phase 6（引擎）依赖 Phase 3（P/Invoke）+ Phase 2（规则表）
- Phase 7（GUI）依赖 Phase 2（配置读写）+ Phase 6C（虚拟键码映射）
- Phase 8（集成）在所有模块完成后进行

---

## 建议开发顺序

1. **Phase 1** → 2. **Phase 2 + Phase 3**（并行） → 3. **Phase 4** → 4. **Phase 5** → 5. **Phase 6A → 6B → 6C** → 6. **Phase 7A → 7B → 7C → 7D → 7E** → 7. **Phase 8**

共计 **43 个任务步骤**，每步粒度控制在可独立编码和验证的范围内。
